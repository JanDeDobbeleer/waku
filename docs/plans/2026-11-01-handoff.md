## 1. What wabar is now

wabar is a C++20/Qt 6.10 Qt Quick shell engine for Windows, configured in QML. It speaks
Quickshell's vocabulary (`ShellRoot`, `PanelWindow`, `Variants`, `Quickshell.Io`, ...) so that shells
written for Quickshell on Linux can be ported to Windows. It also ships built-in widgets and a
sample bar (`examples/config`).

  Its first parent `01184aa` is the Qt Quick line (the old branch `perf/lazy-surfaces`); its

## 2. The goal

Users port Quickshell shells to Windows with wabar. The first reference is
https://github.com/caelestia-dots/shell. The port is a user config home outside this repository.

The rule that governs everything (`AGENTS.md`, "Shells are configuration, not engine"):

- A shell is configuration. It carries its own tokens, palette, layout and styling.
- The engine holds only what QML cannot do and generic Quickshell compatibility. No type, property,
  name or default exists for one shell only.
- A shell under a licence that is not MIT stays out of this repository entirely. caelestia is
  GPL-3.0; wabar is MIT (`LICENSE`).

The owner decided on 2026-10-30 that the generic Quickshell types (`ScriptModel`,
`PersistentProperties`, `IpcHandler`, `Quickshell.Widgets`, the `Quickshell.Services.*` modules, ...)
live in the engine; caelestia's own types (`Config`, `Tokens`, `Colours`, state) stay in the port.
Where each Quickshell type lives: `src/quickshell/README.md`.

## 5. How to work

### 5.1 Safety rules

- Never touch the production bar, its config home or `%USERPROFILE%\.config\wabar` from a test.
- Never click or send input to the desktop. Probe with `wabarc`, `WindowFromPoint`,
  `GetForegroundWindow` and screenshots.
- Never change the wallpaper outside a dry run.
- `AGENTS.md`, "Live desktop rules", is the full list.

### 5.2 A private instance

A private instance uses its own config home, so `wabarc` talks to it and not to the production bar.

1. Make a copy or a `git worktree` of the port (for example under `D:\wabar-ports\wt\<task>`). Never
   run a test on `D:\wabar-ports\caelestia` itself.
2. Point `LOCALAPPDATA` at an empty private folder, so the QML disk cache, the taskbar marker, the
   thumbnails and the state files are private.
3. Set `CAELESTIA_DRYRUN=1` (the port logs actions instead of running them) and
   `WABAR_WALLPAPER_DRYRUN=1` (the engine never sets a wallpaper or lock screen).
4. Start `wabar.exe --config-home <copy> --import-path <copy>\modules --no-tray
   --font-engine=directwrite`. Never add `--register-app-bar` or `--hide-taskbar`. Adding
   `--no-hotkeys` (fire shortcuts with `wabarc shortcut <name>`) and `--no-workarea-sync` keeps the
   run further away from the live desktop.
5. Drive it with `wabarc --config-home <copy> status|reload|call ...|quit`. In the first seconds after
   start `wabarc` can answer "no answer": retry after a second.
6. End with `wabarc --config-home <copy> quit`.

The port's `tools\run.ps1`, `probe.ps1` and `dryrun.ps1` do most of this; pass `-ConfigHome` (they
default to their own folder).

### 5.3 Screenshots

- A screen capture (`tools\shot.ps1`) shows private windows too: crop to the part you need
  (`tools\crop.ps1`) and delete the full captures.
- A locked session gives black frames. Check the session before you trust a capture.

### 5.4 Changing the port

- Work in a worktree of the port, then merge into `D:\wabar-ports\caelestia` `main`.
- The production bar watches that folder. Stop it first (`wabarc --config-home
  D:\wabar-ports\caelestia quit`, or `tools\panic.ps1`), or merge only small QML changes that
  hot-reload cleanly. Restart with the command line of section 4.

### 5.5 Build, check and deploy

The laptop runs one build at a time. Use low priority and few jobs: BelowNormal, 2 to 4 jobs (put
the command in a `.cmd` file and run `start "" /belownormal /wait <file>.cmd`), filtered `ctest`
while you work, and the full `tools\check.ps1` once at the end.

```powershell
$vc = 'C:\Program Files (x86)\Microsoft Visual Studio\2022\BuildTools\VC\Auxiliary\Build'

# Fast checks (format, structure, json-subscript): before every commit
pwsh -NoProfile -ExecutionPolicy Bypass -File tools\check.ps1 -Fast

# Filtered tests while working (one ctest entry per gtest suite)
cmd /c "call `"$vc\vcvarsarm64.bat`" && set VCPKG_ROOT=C:\vcpkg&& cmake --build --preset arm64-debug -j 3 && ctest --test-dir build\arm64-debug -R Tray --output-on-failure --timeout 120"

# Full definition of done, once at the end
$env:CTEST_PARALLEL_LEVEL = '2'; pwsh -NoProfile -ExecutionPolicy Bypass -File tools\check.ps1
```

Release build and deploy (the deployed `dist\wabar` is what the owner runs):

1. Configure without the vcpkg install step, which can hang:
   `cmake --preset arm64-release -DVCPKG_MANIFEST_INSTALL=OFF` (inside the `vcvarsarm64.bat`
   environment, `VCPKG_ROOT=C:\vcpkg`).
2. Build the two executables: `cmake --build --preset arm64-release --target wabar wabarc -j 3`.
3. Stop the production bar: `wabarc --config-home D:\wabar-ports\caelestia quit`. The `deploy`
   target fails while `wabar.exe` runs.
4. `cmake --build --preset arm64-release --target deploy` assembles `dist\wabar`.
5. Restart the bar with the command line of section 4.

If moc or the type registration is skipped after an incremental build (a new QML-facing header is
not found), delete `build\arm64-release\src\wabar_services_autogen\timestamp` (or the same file under
the preset you build) and build again.

`x64-release` is cross-built with `vcvarsarm64_amd64.bat`; its tests run under emulation. Its build
folder was a stale cache from the old `yasb-native` folder and has been recreated (now
`CMAKE_HOME_DIRECTORY=D:/wabar`). A build folder made under the old name needs only its
`CMakeCache.txt` and `CMakeFiles` deleted.

### 5.6 Worktrees

- One `git worktree` per task under `D:\wabar-wt\<task>` on its own branch. Remove it when the branch
  is merged.
- The harness blocks `Remove-Item` on some build folders; use `git worktree remove --force <path>`.
- `core.hooksPath` is `D:\wabar\tools\hooks` for every worktree. If a worktree adds a commit scope,
  commit there with `git -c core.hooksPath=tools/hooks commit ...`.

### 5.7 Commits

- Conventional commits: `type(scope): subject`, imperative, lower case, no trailing period. The
  scopes `tools/hooks/commit-msg` accepts include `quickshell` (the compatibility unit) and no longer
  `shell` (folded into `quickshell_io` by `0fc13a0`).
- One logical change per commit; `tools\check.ps1 -Fast` green before each commit (the pre-commit
  hook runs it on staged files), the full check before a merge.
- Agent-authored commits end with the attribution trailer the session instructions give.
- Line endings: CRLF for C++ sources and docs, LF for QML and the git hooks (`AGENTS.md`). Keep
  the ending a file already has.

### 5.8 Agents

- The lead plans, briefs and verifies; cheaper models implement (Sonnet for standard work with an
  exact brief, Haiku for mechanical sweeps). A brief names the files it may touch, the rules, the
  test to write first, the commit scopes and the report format.
- The lead checks every result: diff, tests, and for visible changes a cropped screenshot.
- An independent review at each merge point found real defects in the past (handoff of 2026-10-30,
  section 5). Keep doing it.

### 5.9 Lessons learned (session report unless a commit is named)

- Hot-reload bugs came from stale singletons. `ShellHost::resetEngine()` now destroys the old shell
  and clears the singletons and the component cache before the new shell is built
  (`docs/architecture.md`, "Singletons across a reload"). Never keep a pointer to an engine
  singleton across a reload; `93a7a90` fixed one such case in `workspaces`.
- An `as Type` cast in QML returned null in the port. Do not rely on it to narrow a type.
- `wabarc` lost an answer that was already buffered before `waitForReadyRead` (fixed in
  `73f39a3`).
- `SendNotifyMessageW` cannot carry `WM_SETTINGCHANGE`: it fails with error 1159
  (`ERROR_MESSAGE_SYNC_ONLY`). The work area guard uses `SendMessageTimeoutW` (250 ms).
- The scene graph texture atlas made the D3D11 driver keep hundreds of MB of atlas copies after the
  launcher's icon uploads. `wabar.exe` sets `QSG_ATLAS_SIZE_LIMIT=1` unless the caller set it
  (`01184aa`; numbers in `docs/reviews/2026-10-31-memory-profile.md`, "Atlas copies").
- `--font-engine=directwrite` maps every installed font the first time the dashboard opens (about
  1,760 handles). That is normal, not a leak.

## 8. Known limits (still true from the previous handoff)

- Out for good on Windows: session lock and PAM, being the notification server and invoking toast
  actions, DBus tray menus rendered in QML, compositor blur that follows alpha, Hyprland special
  workspaces and `dispatch`, exclusive keyboard focus.
- A shell that needs variable-font axes must start `wabar.exe --font-engine=directwrite`.
- `QSG_RHI_BACKEND=d3d12` doubles idle memory; do not use it (memory profile).
- The `windeployqt` post-link step of `wabar_tests` failed once with "does not seem to be a Qt
  executable"; deleting the exe and building again fixed it.
