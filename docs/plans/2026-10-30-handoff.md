# Handoff: Quickshell-compatible engine and the caelestia port

Status: handoff, 2026-10-30. Read this first if you continue the work (a person, Copilot or another
agent). It records what is done, what is left, and how to work. The plan behind it is
`2026-10-30-delivery-plan.md`; the reasons are in `2026-10-29-wabar-extensibility-proposal.md`
(section 11 wins on names) and `2026-10-30-caelestia-port-assessment.md`.

## 1. The goal

Users port existing Quickshell shells to Windows with wabar. The reference is
https://github.com/caelestia-dots/shell. The run ends when a port of caelestia loads, responds, and
has been checked by looking at screenshots (section 6). The engine is Quickshell-compatible in names
and semantics where Windows allows it.

Rule for everything below: shells are configuration. The caelestia port lives outside this
repository and carries its own styling; the engine only gets generic Quickshell compatibility
(see `AGENTS.md`, "Shells are configuration, not engine").

## 5. How to work

- Read `AGENTS.md` first. It is the contract: layout, rules S1-S8, style, error handling, live
  desktop rules, commits.
- Build and test: use `pwsh`. `tools\check.ps1` runs format, structure, json-subscript, build
  (`arm64-debug`) and the full `ctest`. It must exit 0 before a commit that changes code.
- Git hooks: `git config core.hooksPath tools/hooks`. In a worktree, `core.hooksPath` points at the
  main checkout's hooks, which may not know a new commit scope. Use
  `git -c core.hooksPath=tools/hooks commit ...` from the worktree. When you add a feature, add its
  scope to `tools/hooks/commit-msg` and `AGENTS.md`.
- Stale build cache: a build folder made under the old name `yasb-native` carries a wrong
  `CMakeCache.txt`. Delete only `CMakeCache.txt` and `CMakeFiles` in `build\<preset>`.
- Live desktop: always pass `--config-home <dir>` and `--no-tray` to `wabar.exe`. Never use
  `--register-app-bar` in tests. Never click or send input; probe with `WindowFromPoint`,
  `GetForegroundWindow` and screenshots. Never touch `%USERPROFILE%\.config\wabar`.
- Merging lanes: conflicts have all been additive (CMake source lists, scope lists, rows in
  `docs/architecture.md`, `wabarc` help text). Keep both sides. After a merge, run the full check
  before you commit; the commit hook runs the format check and refuses unformatted files
  (`C:\Program Files\LLVM\bin\clang-format.exe -i <file>`).
- Models for new work: Opus for a breaking or architecture-wide step; Sonnet for standard steps with
  an exact brief; Haiku for mechanical sweeps; a read-only reviewer on a different model at each gate.
  A brief names the files it may touch, the rules above, the test first, the conventional-commit
  scopes, and a report format. Keep concurrent builds to three (12 cores; a full build takes about
  10 minutes).
- Reviews found real defects at each gate (gate 1: validation that destroyed a live shell; gate 2:
  an inverted mask). Keep an independent review at every merge point.

## 6. The caelestia port and its validation

1. List the modules in order: window shell and drawers, bar, launcher, OSD, session menu,
   notification list, dashboard, sidebar.
2. Replace caelestia's C++ plugin (`Caelestia.*`: `Config`, `Tokens`, `I18n`, `State`, ...) with pure
   QML singletons in the port where possible; build a user plugin in `<config home>/modules` only
   where QML cannot do it. Stub Linux-only data (Hyprland IPC, `nmcli`, `brightnessctl`, `cava`,
   `/proc`) visibly.
3. Port one module per worker, in separate worktrees of the port folder, with disjoint files. Each
   worker records engine gaps with the caelestia `file:line`.
4. Run `wabar.exe --config-home D:\wabar-ports\caelestia --no-tray`. Take screenshots with
   `System.Drawing` (read-only): the whole screen, and each module open and closed.
5. Compare with the images in caelestia's README. List each difference as a Windows limit, a wabar
   gap or a port bug. File gaps as work items in `docs/plans/` with a size.
6. Success: bar, launcher, session menu and notification list render and respond; drawers open and
   close with their animations; input passes through the empty regions; every difference is explained.

## 7. Known limits and what was not verified live

- Never run on a real desktop: `RegisterHotKey` delivery, a real app bar reservation, `SetWindowPos`
  and `WS_EX_NOACTIVATE` effects, the real `GetCursorPos` poll under mixed DPI, `ShellExecuteEx` and
  `runas`, `activateAppByAumid`, `IAudioSessionManager2`, the `DesktopState` probes, the real GPU
  counter values. All are covered with fakes only. Check each once by hand before a release.
- Out for good on Windows: session lock and PAM, being the notification server and invoking toast
  actions, DBus tray menus rendered in QML, compositor blur that follows alpha, Hyprland special
  workspaces and `dispatch`, exclusive keyboard focus.
- A shell that needs variable-font axes must start `wabar.exe --font-engine=directwrite`.
- The `windeployqt` post-link step of `wabar_tests` failed once with "does not seem to be a Qt
  executable"; deleting the exe and rebuilding fixed it.
- After adding QML-facing headers an incremental build may skip moc for `wabar_services`; delete
  `build\arm64-debug\src\wabar_services_autogen\timestamp` and rebuild.
