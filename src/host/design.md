# host: runtime notes

Mechanism notes for the shell runtime that do not fit a table row of `docs/architecture.md`. The rows there keep owner, work and stop.

## Notes moved from docs/architecture.md

The thread and singleton tables there keep one line per cell. This is the longer text of their rows before they were shortened.

- `Quickshell.Services.UPower.UPower`, `PowerProfiles`; `Quickshell.Services.Pipewire.Pipewire`; `Quickshell.Services.SystemTray.SystemTray`; `Quickshell.Bluetooth.Bluetooth`; `Quickshell.Hyprland.Hyprland` (and the enum singletons beside them) (`src/quickshell/{services/upower,services/pipewire,services/systemtray,bluetooth,hyprland}/*.qml`): QML singletons, as the Quickshell ones are. Each reads the wabar service singletons (`Battery`, `ControlCenter`, `AudioOutput`, `AudioInput`, `AudioStreams`, `Systray`, `Bluetooth`) through one replaceable `backend`/`service`/`output` property that tests set to a fake; none owns a thread or a native resource. Created by the engine on first use, GUI thread only

- `GlobalShortcut` (`src/host/qml/global_shortcut.{h,cpp}`) owns no hotkey state: it adds its keys to `kernel::Hotkeys` (`src/kernel/qt/hotkeys.{h,cpp}`), the global hotkey table of a `wabar` run. The table moved to the kernel because the wallpaper gallery hotkey uses it too, and a feature may not include `host/`. It is a singleton (see the singleton table in `docs/architecture.md`): it maps key combinations to callbacks (two users on one combination share one registration and both fire) and owns the one `HotkeyBackend`, `RegisterHotKey` (documented) with a null window and a native event filter on the GUI thread (`src/kernel/win32/hotkeys_win.cpp`). Every id is unregistered when its last user goes and, at the latest, in the destructor. Inert, no backend, when `kernel::liveDesktop("hotkeys")` is false (offscreen platform, `--no-hotkeys`). Tests install a fake (`src/kernel/testing/hotkeys_fixtures.h`)

- `wabar.Thumbnails` (`src/host/qml/thumbnails.{h,cpp}`, store `src/host/thumbnail_store.{h,cpp}`): `url(path, width)`, `prewarm(paths, width)` and `cancelPrewarm()` for a gallery of large images, and the owner of the `image://thumb/<path>?w=<px>` provider (registered by `create()`, as `AppsService` registers `appicon`). A singleton because QML needs an object to call and the provider belongs to the engine that creates it; it holds the shared `ThumbnailStore` (memory LRU of 64 MB, disk cache `%LOCALAPPDATA%\wabar	humbs`, keyed by SHA-1 of path, width, mtime and size, WebP q85 or PNG) and the prewarm pool. GUI thread only; created on first use. No disk cache, memory only, unless `kernel::liveDesktop("thumbnails")`
